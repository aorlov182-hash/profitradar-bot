# ProfitRadar MP — Architecture

## Общая архитектура системы

ProfitRadar MP — это масштабируемая система аналитики прибыли для продавцов маркетплейсов Wildberries и Ozon.

Главная задача проекта — помочь селлерам контролировать реальную прибыль товаров с учетом:

- закупочной стоимости;
- комиссии маркетплейса;
- логистики;
- возвратов;
- рекламы;
- дополнительных расходов.

Проект развивается поэтапно:

Telegram Bot → Backend Platform → Marketplace Analytics → AI Assistant

Архитектура создается таким образом, чтобы MVP можно было быстро запустить, а затем постепенно превратить в полноценную SaaS-платформу.

---

# Текущая версия MVP

На этапе MVP используется упрощенная архитектура.

Основные задачи MVP:

- быстрый расчет прибыли товара;
- проверка востребованности продукта;
- получение первых пользователей;
- сбор обратной связи;
- подготовка основы для PRO версии.

Текущий подход:

Минимум сложных компонентов → быстрый запуск → постепенное масштабирование.

# Backend слой

Backend отвечает за основную бизнес-логику приложения.

Назначение:

- обработка расчетов;
- управление пользователями;
- работа с базой данных;
- подготовка API;
- управление подписками.

Текущая реализация:

Часть логики находится внутри Telegram Bot.

Будущее развитие:

Вынос бизнес-логики в отдельный Backend API.

Планируемая технология:

- FastAPI

# База данных

## Текущая версия

Используется:

SQLite

Назначение:

- хранение пользователей;
- сохранение расчетов;
- работа MVP;
- хранение настроек.

Преимущества текущего решения:

- простота;
- быстрый запуск;
- отсутствие сложной настройки;
- подходит для первых пользователей.

---

## Будущий переход

SQLite → PostgreSQL

Причины перехода:

- масштабирование проекта;
- большое количество пользователей;
- многопользовательский режим;
- высокая скорость запросов;
- надежность хранения;
- сложная аналитика данных.

Слой интеграции с маркетплейсами.

- Ozon API.

- получение комиссий;
- учет расходов;

- автоматический расчет прибыли.

# AI Analytics Engine

Интеллектуальный аналитический модуль.

Главная задача:

Помочь продавцу принимать решения на основе данных.

Возможности:

- поиск убыточных товаров;
- анализ реальной прибыли;
- рекомендации по изменению цены;
- прогнозирование доходности;
- поиск точек роста;
- автоматические советы продавцу.

Пример анализа:

"Товар имеет хорошие продажи, но после учета комиссии маркетплейса, рекламы и возвратов фактическая прибыль отрицательная. Рекомендуется увеличить цену на 7% или пересмотреть расходы."
