# ADR-003 — Использование PostgreSQL как основной базы данных

Дата:

26.07.2026

Статус:

Accepted


# Контекст

На этапе MVP ProfitRadar MP использует SQLite для быстрого запуска и тестирования.

Однако дальнейшее развитие проекта требует перехода на полноценную серверную базу данных.


Основные требования:

- работа с большим количеством пользователей;
- хранение истории расчетов;
- хранение товаров;
- управление подписками;
- хранение платежей;
- возможность аналитики.


# Рассмотренные варианты


## SQLite

Плюсы:

- простая настройка;
- не требует отдельного сервера;
- подходит для MVP.

Минусы:

- ограниченная масштабируемость;
- хуже подходит для многопользовательского режима;
- ограниченные возможности при высокой нагрузке.


## MySQL

Плюсы:

- популярная база данных;
- высокая производительность;
- большое сообщество.

Минусы:

- менее удобна для некоторых аналитических задач;
- меньше соответствует выбранному стеку проекта.


## PostgreSQL

Плюсы:

- надежная промышленная база данных;
- поддержка сложных запросов;
- подходит для SaaS-продуктов;
- хорошо работает с Python и FastAPI;
- поддерживает масштабирование.


# Решение

Использовать PostgreSQL как основную базу данных для Production-версии ProfitRadar MP.


# План миграции

Текущий этап:

SQLite

↓

Следующий этап:

PostgreSQL


Перенос будет включать:

- создание структуры таблиц;
- миграцию данных;
- настройку подключений;
- тестирование запросов.


# Последствия


Положительные:

- готовность к росту количества пользователей;
- возможность создания полноценной аналитики;
- надежное хранение данных;
- поддержка подписочной модели.


Отрицательные:

- требуется настройка сервера базы данных;
- необходимо управление миграциями.


# Обоснование

SQLite оптимален для MVP и проверки идеи.

PostgreSQL выбран как целевая база данных для стабильной коммерческой версии ProfitRadar MP.
