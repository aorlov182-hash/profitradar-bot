# 3. Архитектурные проблемы

## 3.1 Монолитная структура

Сейчас:

Telegram Bot + бизнес-логика + база данных находятся в одном приложении.


Проблема:

При росте пользователей будет сложно:

- масштабировать;
- добавлять Web API;
- подключать сайт;
- подключать мобильное приложение.


Решение:

Выделить Backend API.


---

## 3.2 SQLite

Текущая БД подходит для MVP.

Ограничения:

- один файл базы;
- слабая работа при большом количестве запросов;
- нет полноценного многопользовательского режима.


План:

SQLite → PostgreSQL


---

## 3.3 Отсутствие API слоя

Сейчас:

Telegram напрямую вызывает функции приложения.


Будущее:

Telegram Bot

↓

Backend API

↓

Database
