# ProfitRadar MP — Авторизация

## Назначение

ProfitRadar MP использует единую систему авторизации для всех компонентов платформы.

Все клиенты работают с одной учетной записью пользователя:

- Telegram Bot
- Android App
- Website
- Backend API

---

# Основной принцип

Пользователь не создает отдельный логин и пароль.

Единственным способом входа является авторизация через Telegram.

Это позволяет:

- не хранить пароли;
- упростить регистрацию;
- повысить безопасность;
- использовать одну учетную запись на всех устройствах.

---

# Схема авторизации

Авторизация происходит следующим образом:

1. Пользователь открывает Android-приложение или сайт.
2. Нажимает кнопку «Войти через Telegram».
3. Открывается Telegram-бот ProfitRadar MP.
4. Пользователь подтверждает вход.
5. Backend API проверяет пользователя.
6. Backend выдает JWT Access Token.
7. Backend выдает JWT Refresh Token.
8. Приложение сохраняет токены.
9. Пользователь получает доступ к системе.

---

# JWT

Используются два токена.

## Access Token

Назначение:

Доступ к Backend API.

Время жизни:

15 минут.

После окончания срока действия используется Refresh Token.

---

## Refresh Token

Назначение:

Получение нового Access Token.

Время жизни:

30 дней.

Refresh Token никогда не используется для обращения к API напрямую.

---

# Проверка пользователя

Backend API проверяет:

- Telegram ID;
- существование пользователя;
- статус подписки;
- статус блокировки;
- срок действия токена.

После успешной проверки возвращаются данные пользователя.

---

# Выход из системы

При выходе:

- Access Token удаляется;
- Refresh Token удаляется;
- устройство отвязывается от текущей сессии.

Повторный вход требует новой авторизации через Telegram.

---

# Несколько устройств

Один пользователь может использовать:

- телефон;
- планшет;
- компьютер;
- веб-кабинет.

Все устройства работают с одной учетной записью.

---

# Защита данных

Backend никогда не хранит:

- пароли;
- PIN-коды;
- секретные данные пользователя в открытом виде.

Все конфиденциальные данные передаются только по HTTPS.

---

# Хранение токенов

Android:

- защищенное локальное хранилище (Secure Storage).

Website:

- защищенные HTTP-only Cookie или безопасное локальное хранилище.

Telegram Bot:

- авторизация выполняется автоматически через Telegram ID.

---

# Безопасность

Для защиты системы используются:

- HTTPS;
- JWT;
- ограничение времени жизни токенов;
- защита от повторного использования Refresh Token;
- проверка подписи токенов;
- серверная проверка прав доступа.

---

# Будущее развитие

Планируется добавить:

- вход по QR-коду;
- управление активными устройствами;
- возможность завершения всех сессий;
- двухэтапное подтверждение критических операций;
- журнал авторизаций.

---

# Итог

Авторизация должна быть максимально простой для пользователя и максимально безопасной для системы.

Telegram выступает единой точкой входа, а Backend API отвечает за управление доступом и проверку прав пользователя.
